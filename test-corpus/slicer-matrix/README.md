# Slicer matrix corpus

Written by an AI agent (Claude). Our own test models (generated by `scripts/models.py`, MIT like the rest of this repo), sliced on 2026-10-10 by real installed slicers, and the values each slicer stated about its own output. Because we made the models, the sliced files can live in the repo; third-party samples stay out (see docs/reference-data.md).

| Prefix | Slicer | Printer / filament presets |
|---|---|---|
| P | PrusaSlicer 2.9.6 | Original Prusa MK4S 0.4, 0.20mm SPEED, Prusament PLA/PETG (bundle presets flattened by `flatten_ini.py`) |
| B | Bambu Studio 02.08.02.61 | Bambu Lab P1S 0.4, 0.20mm Standard, Bambu PLA Basic / PETG HF |
| O | OrcaSlicer 2.4.2 | Creality K1C 0.4, 0.20mm Standard, Creality Generic PLA/PETG |

Cases per slicer: 20 mm cube (PLA, PETG), 5 mm cube (short print), T-shape with supports, vase-mode cylinder, 150×150×60 mm slab at 100 % infill (a 21-28 h print), and an unsliced project 3MF (must be rejected with the matching message). PrusaSlicer also has the cube as binary `.bgcode`, as binary G-code saved with a `.gcode` name (the MK4S default), and as a project 3MF.

`manifest.json` lists every file with `stated_weight_g` / `stated_time_s` (read from the file by `truth.py`, independently of our parser) and whether it should parse or be rejected. Three files over 3 MB are listed but not committed (`committed: false`).

To regenerate: install the slicers on Windows, run `models.py <dir>/models`, flatten presets into `<dir>/profiles` (see the commands at the top of each flatten script), then `SHTEST=... SHTEST_WIN=... scripts/run_matrix.sh`. Bambu Studio and OrcaSlicer's CLIs need the system printer preset file plus a flattened filament preset; flattened printer or process presets are refused as "not compatible".
